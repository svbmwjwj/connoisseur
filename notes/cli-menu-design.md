# cnsr 命令与功能菜单设计

## 背景

分层第一阶段之后，服务器层（地址、接管、加固）和 Xray 层已经分开，但命令仍然只有一条 `add`，一路部署到 Xray。用户希望能只做加固，并且觉得 `add`、`rm`、`list` 这组命令搭配不好。

已在分支 `feat/up-menu` 上实现，见文末“实现情况”。分层本身见同目录的 `layering-design.md`。

## 一级菜单

- 菜单项：不带参数运行 `cnsr` 时弹出一级菜单，只有三项：部署服务器、删除服务器、服务器列表（用户，D-003）。
- 对应命令：三项各有一条可以直接运行的命令：`cnsr up [别名]`、`cnsr rm <别名>`、`cnsr list`（用户：部署命令叫 `up`，D-006；其余 Claude）。
- 不在终端里时：没有菜单可选，`cnsr` 不带参数照旧打印帮助（Claude）。
- 旧命令：删除 `add`，不保留兼容别名（用户，D-005）。
- 来源参数：`--aws <区域>`、`--ip <IP>`、`--static-ip <IP>` 移到 `up` 下，含义不变；不带参数时照旧逐项询问（Claude）。

## 部署时的功能选择

- 方式：`up` 选完服务器来源后弹出多选菜单，不用命令行参数选功能（用户，D-004）。
- 菜单项：上方是基础功能“基础加固”，下方是扩展功能，目前只有“Xray 节点”（用户，D-004）；2026-11-22 起扩展功能是“Docker”和“Xray 节点”两层，见下文“Docker 层”（用户，D-008）。
- 依赖：勾选了扩展功能，就必须同时勾选基础加固才能继续；只勾基础加固可以；一项都不勾不能继续（用户，D-004）。
- 默认：两项都勾选，即现在的完整流程（Claude）。
- 不在终端里时：按默认两项都部署（Claude）。
- 只选基础加固：只跑现在的第 1～3 步，即确定地址、接管预检并建 DNS 解析和 SSH 别名、加固；阶段列表只显示这 3 步（用户：做到第 1～3 步；其余 Claude）。

## Docker 层

- 层级：基础加固 → Docker → Xray 节点，每层依赖它上面的所有层；勾选一层时自动勾上它上面的层，取消一层时它下面的层一起取消（用户提出，规则 Claude，D-008）。
- 参数：`--to` 可选 `base`、`docker`、`xray`（Claude）。
- 步骤：Docker 单独成为第 4 步“安装 Docker”，Xray 的步骤顺延为第 5～9 步，不再各自安装 Docker（Claude）。
- jq：只有换 SNI 的服务用到，改由第 9 步通过 `install-docker.sh jq` 补装，只到 Docker 的服务器不装（Claude）。
- 端口：只到 Docker 时不放行任何应用端口，用户自己的服务端口由用户自己处理（用户，D-008）。小厂商服务器上，容器用 `-p` 发布的端口会绕过 ufw，已写进 `docs/README.md`（Claude）。
- 旧记录：记录里有 Xray 而没有 Docker 的，读取时视为也有 Docker，不需要迁移（Claude）。
- 展示：`cnsr list` 中只到 Docker 的服务器显示为“Docker”，标记为 `◐`（Claude）。

## 已有服务器再次部署

- 菜单：对已有别名运行 `up` 时同样弹出功能菜单，已经部署的功能显示为已勾选且不能取消（Claude）。
- 补装：只做过加固的服务器，勾上 Xray 后从第 4 步接着部署；第 1～3 步照旧检查一遍（Claude）。
- 卸载：这次不做卸载某个功能，要去掉只能删除整台服务器（Claude）。

## 端口与防火墙

只选基础加固时，服务器层不放行任何应用端口（Claude）：

- 预检：`evaluate` 的 `app_ports` 传空，不检查 443。
- AWS：Lightsail 防火墙只放行 22。
- 小厂商：`harden-stage.sh:216`～`:217` 现在写死了 `ufw allow 443/tcp`、`443/udp`，是分层第一阶段漏掉的耦合；改成由 cnsr 把应用端口作为参数传入。
- 补装 Xray：重跑时第 3 步按 Xray 的端口重新设置防火墙；小厂商机器已经加固过时，第 3 步在补全加固之后用 `ufw allow` 补开所选功能的端口（Claude，D-007）。

## 记录与展示

- 记录：服务器记录里增加已部署功能的列表，例如 `["harden"]` 或 `["harden", "xray"]`；旧记录没有这个字段时，有 `line` 的视为两项都有（Claude）。
- 列表：`cnsr list` 按服务器列出，每台标明功能，例如“Xray 节点”或“仅加固”；圈X 和 v2rayN 的订阅只在有 Xray 节点时显示（Claude）。
- 措辞：帮助、提示和阶段标题里不涉及 Xray 的地方，“节点”改成“服务器”（Claude）。
- 删除：`rm` 的流程不变，只加固的服务器同样删除云资源、DNS、别名和记录（Claude）。

## 影响范围

- 文档：README、`docs/README.md`、`--help` 都要改成新命令。
- 测试：现有测试大量通过 `add` 调用，需要整体改成 `up`。
- 发布：这是对外的命令变化，旧版文档里的 `cnsr add` 会直接报错（用户已接受，D-005）。

## 待定事项

- [x] 部署命令的名字：用 `up`（D-006）。

## 实现情况

- 功能：`src/cnsr/features.py` 定义基础加固和扩展功能、依赖规则与各自的端口；服务器记录新增 `features` 字段。
- 菜单：`menu.select_many` 是勾选菜单，`Ui.choose_many` 在没有菜单时改用编号输入；`cnsr` 不带命令时弹出一级菜单。
- 流水线：只选基础加固时只跑第 1～3 步；AWS 失败清理改为只在“这台服务器从没完成过任何一次部署”时进行，避免补装 Xray 失败时删掉已加固的实例。
- 端口：`harden-stage.sh` 改为接收第 4 个参数，只放行传入的端口。
- 测试：新增 `tests/cnsr/test_up_features.py`，Python 1991 个、Worker 107 个测试通过；还没有在真机上跑过只加固的流程。
