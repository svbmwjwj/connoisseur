###### cnsr 进度显示与运行日志 设计

2026-10-18 真机测试时提出。适用于 `cnsr add` 和 `cnsr rm`，是对 `cnsr-redesign-spec_zh-cn.md` 的补充，命令和参数不变。

**为什么**

真机测试时，每次出问题都要你把终端输出复制给助手，输出里又夹着大量过程细节。一般用户只需要知道现在到了哪个环节、程序还在跑，细节留给排查问题的人看。

**目标**

— 屏幕只给人看 — 显示当前环节、整体进度和一个持续转动的运行指示，过程细节不上屏。
— 每次运行都有日志 — `add` 和 `rm` 每次运行自动写一个日志文件，足够让人不看屏幕也能还原发生了什么、卡在哪里。
— 助手可以直接读 — 你说“跑完了”，助手读最新的日志文件，不需要你复制粘贴。

**不做的事**

— 不加命令和参数 — 不加 `--verbose`、`--quiet`、`logs` 子命令，帮助菜单保持原样。
— 不估算剩余时间 — 各环节耗时差别太大，估算只会误导。
— 不上传日志 — 日志只留在本机，cnsr 不发送到任何地方。

**会让这件事失败的情况**

— 日志里出现任何密钥或 token。
— 进度动画盖住了需要你回答的问题，或者 OpenSSH 的密码提示。
— 输出被重定向到文件或管道时，文件里全是动画控制字符。
— 出错时屏幕上看不到错误原因，只能去翻日志。

**屏幕：运行中**

```text
cnsr add cnsr-test-1 · AWS 东京

  ✓ 确定服务器地址                    0:12
  ✓ 连接服务器并建解析                 1:05
  ✓ 加固                              0:08
  ⠹ 扫描候选 SNI      1534 / 3071      1:12
  · 在节点上验证并选定 SNI
  · 部署 Xray
  · 登记节点并切换 SSH 别名

  ━━━━━━━━━━━━━━━━──────────────  3/7   已用时 2:37
```

— 标题行 — 命令、别名和来源（AWS 区域，或“已有服务器 <IP>”）。
— 环节列表 — 一开始就列出全部环节：做完的打 ✓ 并显示耗时，当前的前面是转动的符号、后面是每秒刷新的计时，没轮到的是灰色的点。
— 整体进度条 — 按完成的环节数计算，旁边显示“完成数/总数”和总用时。
— 环节内的数量 — 能数得清的环节在当前那一行显示数量，至少包括扫描（已扫地址数/总数）。其他环节只显示转动符号和计时。
— 准备阶段 — 环节列表出现之前（检查控制端、询问凭据、选钥匙），用一行转动的“准备中”加当前在做什么，例如“检查 Cloudflare 控制端”。
— `rm` 的环节 — 确认删除之后显示同样的界面，环节为：删除 AWS 实例和静态 IP（小厂商节点没有这一环节）、删除 DNS 记录、删除 SSH 别名、删除控制端登记。

**屏幕：上屏的只有这几类**

— 问题 — 需要你回答的问题（方向键菜单、输入框、`已保存` 这类确认）。提问时进度区先收起，留下一行当前环节（例如“[4/7] 扫描候选 SNI”），问题和它前面必须读的说明出现在这一行下面。你的回答留在屏幕上，答完后完整的进度区重新出现在最下面，屏幕上始终只有一份进度区。
— OpenSSH 自己的提示 — 例如小厂商服务器第一次登录时 OpenSSH 询问 root 密码，处理方式同上，并把终端完全交给 ssh。
— 控制台密码 — 小厂商加固时生成的控制台密码显示在会被收起的区域里，你输入“已保存”后从屏幕上清掉。
— 警告 — 以“警告：”开头，出现在进度区上方并一直保留。
— 错误 — 当前环节变成 ✗，进度区下方显示错误原因（与现在屏幕上的错误原文一致），然后是自动清理的过程和结果，最后一行是日志路径。
— 中断 — Ctrl-C 时当前环节标为“已中断”，同样显示清理结果和日志路径。
— 结束 — 成功时进度区下方显示节点就绪的一句话、圈X 配置和策略组提示，最后一行是日志路径。

**屏幕：没有终端时**

标准输出不是终端时（重定向到文件、管道、CI），不画动画和进度条，只逐行输出：每个环节开始一行、结束一行（带耗时），警告、错误、结束内容照常输出。

**日志：位置和文件**

— 目录 — cnsr 配置目录下的 `logs/`：macOS 和 Linux 是 `~/.config/cnsr/logs/`（遵守 `XDG_CONFIG_HOME`），Windows 是 `%APPDATA%\cnsr\logs\`。
— 文件名 — `<命令>-<别名>_<YYYYMMDD-HHMMSS>.log`，例如 `add-cnsr-test-1_20261018-153012.log`、`rm-cnsr-test-1_20261018-160501.log`。不带别名运行 `add` 时，问到别名后再定文件名。
— 何时写 — 只有 `add` 和 `rm` 的一次运行写日志。帮助、版本和命令行参数错误不写。
— 权限 — 只有当前用户可读写，与 `secrets.env` 的做法一致（Unix 600，Windows 用 ACL）。
— 保留 — 只保留最近 20 个日志文件，每次运行结束时删除更早的。
— 结束时提示 — 不论成功、失败还是中断，屏幕最后一行都是 `日志：<完整路径>`。

**日志：内容**

每行带本地时间（精确到毫秒）和级别，UTF-8，LF 换行。至少包含：

— 开头 — cnsr 版本、命令行参数、操作系统和 Python 版本、开始时间。
— 屏幕上出现过的全部内容 — 问题、你的选择（菜单选了哪一项、输入了什么；密码和密钥类输入除外）、警告、错误。
— 环节 — 每个环节的开始、结束、耗时和结果（完成、失败、中断）。
— 过程细节 — 现在打印到屏幕上的过程信息（例如“安装 Docker”“节点验证了 30 个候选，通过 25 个”“选定 SNI”），全部改为只写日志。
— 远程命令 — 每条 SSH 命令和脚本：目标地址、命令或脚本名、退出码、耗时；失败时再加 stdout 和 stderr 各自的最后若干行。成功的命令不记输出。上传的文件不记内容，只记路径和权限。
— 云 API — 每次 Cloudflare 和 AWS 调用：方法和路径（或 boto3 操作名）、HTTP 状态或错误码、耗时。不记请求体和响应体。
— 外部检查 — 直连检查的结果（两边看到的地址、DNS 是否是虚拟地址）、外部探测、公共 DNS 查询的结果。
— 扫描 — 扫描范围、地址数、命中数、过滤后数量、带 SNI 握手成功数，以及进入节点验证的候选（域名和 IP）。
— 结尾 — 结束时间、总耗时、退出码。

**日志：绝不写入**

— 凭据 — Cloudflare API token、AWS access key ID 和 secret access key。
— 控制端 — 客户端 token、管理 token、节点 token。
— 节点 — Xray 私钥和 UUID。shortId、公钥和 SNI 可以写，它们本来就在圈X 配置行里。
— 密码 — 小厂商加固时生成的控制台密码，以及任何你输入的密码。
— 做法 — 写入前，每一行都要把已知的敏感值替换成 `***`。敏感值在出现的那一刻登记（读入 `secrets.env`、你输入、生成或从节点读回时）。登记之前就可能出现在输出里的内容（例如 `xray x25519` 的输出、`cat config.json` 的内容），一律不写输出。

日志里会有节点的 IP、域名和控制端域名，这是排查需要的。所以日志只给自己和助手看，不要公开贴出去。

**已经定下的做法**

— 进度显示用 rich 库 — 由助手决定：它能在 macOS、Linux 和 Windows 的新旧控制台上画进度和转动符号，并能在提问前后停住和恢复。
— 现有输出分两级 — 现在的 `ui.info` 分成两种：你必须读到的（问题前的说明、控制台密码、结束时的配置）照旧上屏，其余过程信息改为只写日志。
— 菜单不变 — 方向键菜单（questionary）照旧，提问时停住进度显示。

**助手的决定（请过目）**

审阅时发现的两处，由助手决定：

— 提问时的画面 — 见上面“问题”一条：收起进度区、留一行当前环节，问答留在屏幕上，进度区始终只有一份。这样既看得出是哪个环节在问，又不会让同一份环节列表在屏幕上重复出现好几次。
— OpenSSH 询问 root 密码那一次 — cnsr 不截取 ssh 的输出，日志里只记这次登录的结果和退出码。截取需要在三个平台上做终端转接，容易把密码提示弄坏，而这正是要避免的失败情况。这次登录失败时，原因照旧在屏幕上 ssh 自己的输出里。
— 控制台密码 — 你输入“已保存”后从屏幕上清掉，减少截图或旁人看到的机会。

**留给实现者**

— 日志的具体行格式、级别名称、失败时输出摘录的行数。
— 转动符号的样式和颜色，进度条宽度，终端太窄时怎么截断。
— 具体哪些 `ui.info` 调用改为只写日志，按上面的规则逐个判断。
— 日志写入和敏感值替换放在哪一层，以及远程命令、云 API 调用在哪里接入日志。

**测试要求**

— 敏感值 — 跑一次完整的假部署（现有的 `deploy_fakes`），确认日志里不出现任何 token、密钥、私钥、UUID 和控制台密码。
— 界面 — 非终端输出时只有逐行文字、没有控制字符；提问时进度显示停住、问题完整可见；出错时屏幕上有错误原文和日志路径。
— 日志文件 — 文件名、权限、只保留 20 个、中断时也写完结尾。
— 平台 — 与现有测试一样，三个平台都要能跑通。
